# Додаток: порівняльна шпаргалка за версіями .NET

Цей додаток — короткий довідник для співбесід про сучасну лінійку випусків .NET (.NET 5 і новіші версії — уніфіковану кросплатформну наступницю .NET Core і .NET Framework). Він навмисно стислий: достатньо, щоб чітко відповісти на співбесіді, «що змінилося між версіями», але не замінює посібник із міграції. Усі наведені дати й позначення підтримки звірено з офіційною політикою підтримки Microsoft і документацією про випуски (див. **Джерела**).

> **Остання перевірка: липень 2026 року.** Ця сторінка застаріває найшвидше в усій книжці: нова версія .NET виходить щороку в листопаді, а періоди підтримки завершуються за графіком. Перш ніж покладатися на наведені дати, звірте їх з офіційною політикою підтримки: `dotnet.microsoft.com/platform/support/policy`.

## Періодичність випусків: як насправді працює версіонування

Щороку в листопаді виходить одна основна версія; парні версії мають довгострокову підтримку (LTS) протягом 3 років, а непарні — стандартну підтримку (STS): 24 місяці, починаючи з .NET 9, і 18 місяців раніше. Як працюють обидва цикли та як обрати потрібний, пояснено в [розділі 3](#chapter-3-how-net-runs-your-code); підтримання парку сервісів на версіях із чинною підтримкою — це нескінченний цикл оновлень, описаний у [розділі 24](#chapter-24-working-with-legacy-brownfield-code). Тут наведено деталі окремих версій.

Кілька приміток щодо даних у таблиці, які можуть здивувати:
- **Підтримка .NET 9 завершується того самого дня, що й .NET 8** (10 листопада 2026 року), хоча .NET 8 має LTS, а .NET 9 — STS. Це збіг календарних дат: перехід STS на 24 місяці підтримки припав саме на дату завершення підтримки LTS.
- **Підтримка .NET 5 і .NET 7 уже завершилася.** Не використовуйте їх для нових виробничих систем.

## Що принесли окремі версії

### .NET 6 (LTS)
- **Мінімальні API** — можна створити робочу HTTP-точку входу в кілька рядків, без контролерів і зайвих налаштувань `Startup.cs`.
- **Hot Reload** — змінюйте код і одразу переглядайте результат без перезапуску застосунку.
- **Глобальні й неявні директиви using** (завдяки C# 10) та простори імен, обмежені одним файлом, скорочують шаблонний код.
- Перша LTS-версія повністю уніфікованої платформи: SDK, середовище виконання та BCL утворюють єдину платформу для Windows, Linux і macOS.
- Широкі покращення продуктивності та краща публікація в одному файлі й із trimming.

### .NET 7 (STS)
- **Native AOT** з’являється для консольних застосунків: попередня компіляція в нативний бінарний файл без JIT і окремого встановлення середовища виконання забезпечує швидкий запуск і низьке споживання пам’яті.
- Один із найбільших випусків за приростом швидкодії: сотні оптимізацій середовища виконання та бібліотек.
- **Вбудоване обмеження частоти запитів** (`System.Threading.RateLimiting`) для ASP.NET Core.
- **.NET MAUI** (кросплатформний UI-фреймворк, наступник Xamarin.Forms) досягає загальної доступності.
- Покращення мінімальних API: фільтри, типізовані результати та краща підтримка OpenAPI.

### .NET 8 (LTS)
- **Native AOT поширюється на ASP.NET Core** — тепер можна компілювати за допомогою AOT певні веб-API, а не лише консольні застосунки.
- **Blazor уніфікується** в єдину повностекову модель із **режимами рендерингу** (server, WebAssembly, auto) і статичним серверним рендерингом. Тепер один застосунок Blazor може поєднувати різні стратегії інтерактивності.
- **Впровадження залежностей за ключем** — реєструйте та отримуйте різні реалізації сервісу за ключем.
- Подальше підвищення продуктивності, зокрема JIT, GC і базових типів; нові примітиви, як-от `TimeProvider`, допомагають тестувати код, що залежить від часу.
- Безпечна LTS-версія за замовчуванням для більшості виробничих навантажень, поки триває перехід на .NET 10.

### .NET 9 (STS)
- **Інструменти для ШІ:** `Microsoft.Extensions.AI` надає спільну абстракцію для чату й embeddings у різних провайдерів, відображаючи перехід .NET до розробки застосунків на базі LLM і ШІ.
- Подальша **оптимізація продуктивності** середовища виконання та нові можливості налаштування збирача сміття.
- Поступове вдосконалення **Native AOT** (менші бінарні файли, ширша сумісність) і **Blazor** (краще відновлення з’єднання, вдосконалення статичного SSR).
- Покращення спостережуваності та інтеграції з OpenTelemetry.
- Як версія STS, це попередній огляд напрямку розвитку .NET 10: корисний, але з коротшим періодом підтримки.

### .NET 10 (LTS)
- **C# 14** з **extension members** — властивості-розширення, статичні розширення та новий синтаксис блоку `extension`, що узагальнює модель методів-розширень.
- Подальше підвищення продуктивності **JIT і середовища виконання** (оптимізація циклів, інлайнинг, девіртуалізація).
- Розвиток **Native AOT**, **ASP.NET Core** і **.NET MAUI**, а не одна центральна нова функція: LTS-випуск, що зосереджується на вдосконаленні й узгодженні платформи.
- Найновіша LTS-базова версія; рекомендована цільова платформа для нових виробничих застосунків.

## Відповіді для співбесіди

**«Чим відрізняються .NET 6 і .NET 8?»**
Обидві версії мають LTS-підтримку, але між ними два роки. .NET 6 став першою LTS-версією уніфікованої платформи та приніс мінімальні API й Hot Reload. .NET 8 розвинув ці можливості: додав Native AOT для ASP.NET Core, уніфіковану модель режимів рендерингу Blazor, DI за ключем і значне підвищення продуктивності. Отже, .NET 8 — швидша, краще пристосована до AOT і функціонально зріліша версія тієї самої платформи. І, на відміну від .NET 6, вона ще підтримується — до листопада 2026 року.

**«Чим відрізняються .NET Framework і .NET (Core)?»**
.NET Framework (до версії 4.8.x) — застаріле середовище виконання лише для Windows, що постачається разом із Windows і перебуває в режимі обслуговування: нових основних версій не буде. Сучасна .NET (Core, а згодом .NET 5+) — кросплатформна високопродуктивна версія з відкритим кодом, у яку спрямовані всі нові інвестиції. Нові розробки мають використовувати сучасну .NET; .NET Framework слід залишити лише для наявних застосунків, прив’язаних до Windows.

**«Що таке LTS?»**
LTS (Long-Term Support, довгострокова підтримка) — це щорічний випуск із парним номером, для якого Microsoft надає виправлення й оновлення безпеки протягом трьох років. STS (Standard-Term Support, стандартна підтримка) має коротший період: історично 18 місяців, а починаючи з .NET 9 — 24 місяці. LTS обирають, коли потрібна стабільність і повільний, передбачуваний графік оновлень.

**«Що використовувати у виробничій системі: .NET 8 чи .NET 9?»**
Віддавайте перевагу LTS. Підтримка .NET 8 (LTS) і .NET 9 (STS) завершується того самого дня — 10 листопада 2026 року. Тому для нового застосунку з тривалим життєвим циклом перспективнішим вибором зараз буде найновіша LTS-версія — **.NET 10**. Якщо застосунок уже працює на .NET 8, терміново переходити на .NET 9 не потрібно: плануйте оновлення до .NET 10.

**«Що таке Native AOT?»**
Native AOT (Ahead-Of-Time, компіляція наперед) під час збирання перетворює застосунок на автономний нативний виконуваний файл, усуваючи JIT і потребу в окремому встановленні середовища виконання. Це забезпечує дуже швидкий запуск, менше споживання пам’яті та менший розмір розгортання — корисно для контейнерів, serverless-систем і CLI-інструментів. Компроміси: обмежена підтримка reflection і динамічного коду, а також менша кількість сумісних бібліотек. Native AOT з’явився для консольних застосунків у .NET 7, а в .NET 8 поширився на ASP.NET Core.

## Висновок в одному реченні

**Для виробничих систем за замовчуванням обирайте найновішу LTS-версію** (зараз це **.NET 10**, підтримка якої триває до листопада 2028 року). Вибирайте STS лише тоді, коли потрібні найновіші функції й ви готові оновлюватися приблизно кожні два роки.
