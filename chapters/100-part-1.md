# Part 1: Junior → Middle

> **What Part 1 makes you able to do.** Work as a solid middle developer inside one service, without help: write C#, async, web, data-access and messaging code that survives production; explain the mechanism behind each classic trap and the fix for it; find the first cause of a slow or failing endpoint yourself; hold your own in a frontend conversation; and turn vague tickets, estimates and reviews into work the team can rely on.

## How to Read Part 1

Read the chapters in order. Each one teaches the key concepts of its topic by their mechanism: what actually happens, where the trap is, and how to fix it. The harder topics are here too, at the depth a middle developer uses unaided; [Part 2](#part-2-middle-senior) takes the same topics further and adds the wider ones, without repeating what you read here.

Most chapters end with practice:

1. **Prove it.** A program of at most 30 lines that shows the chapter's central mechanism. Run it before you read what it shows. Every program is compiled and tested in [`verify/path`](https://github.com/malyna2/dotnet-handbook/tree/main/verify/path): clone the repository, install the .NET 10 SDK and run `dotnet run --project <Name>` from that folder. Two programs also need Docker, for SQL Server or the Service Bus emulator.
2. **Three questions.** Answer without notes, then open the answers. A "why?" you can't answer is the gap an interviewer's follow-up finds.
3. **Check at work.** The chapter is done when you have found the trap, or proved it absent, in code you own.
4. **Exercises and interview questions,** where the chapter has them.

Before an interview, reread [Part 1 · Pay Attention To](#part-1-pay-attention-to): one table of trap → why it bites → the fix.
