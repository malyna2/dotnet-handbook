# verify/sql — Chapter 7's SQL querying examples, on two engines

Maintainer tooling, not reading material. Chapter 7 (Data Access) teaches joins, grouping, NULL logic, subqueries, CTEs and window functions on a tiny shop. Everything it prints or quotes about those queries runs here, on PostgreSQL 17 and SQL Server 2022, against the same seed.

| Path | What it is |
|---|---|
| `schema.sql` | The portable schema and seed: 4 customers (Cleo has no city, Dan no orders), 8 orders (two of Ada's on the same day and for the same amount; order 16 is a guest checkout with `CustomerId` NULL), 10 order lines, 4 categories. |
| `queries/` | Every SQL block the chapter prints in its querying sections, one file each. `run.py` checks each one is printed character for character in both the English and the Ukrainian chapter. |
| `claims/` | Queries behind a number or a statement in the prose that the chapter doesn't print: row counts per join type, `SUM(DISTINCT)`, `AVG` of an integer, NULL sort order, `NOT IN` and CTE plans, the recursion limit, the errors for a window function or a `SELECT` alias in `WHERE`. |
| `run.py` | Loads the schema on both engines, runs every file on both, and checks the engines agree (rows compared as a multiset) unless `EXPECT` says the chapter describes a difference: then it checks the difference is there. `PLAN_CHECKS` checks the plan text a statement rests on. |
| `EfLinq/` | Prints the SQL EF Core 10 sends for the LINQ forms in the chapter's "SQL Queries in EF Core LINQ" table, and their rows, on both engines; `verify.sh` checks the shapes the table names. |
| `reference-runs/` | Raw output of every file on both engines, plus `ef-linq.txt`, each headed with the environment. Regenerated by every run. |
| `docker-compose.yml` | `postgres:17.11` on port 54317, `mssql/server:2022-CU27-ubuntu-22.04` on port 14317. Development and test only. |

## Run

```bash
verify/sql/verify.sh          # starts both containers, checks, leaves them running
verify/sql/verify.sh --down   # ...and removes them afterwards
```

`verify.sh` sets `ACCEPT_EULA=Y`, which accepts the SQL Server Developer edition EULA for local use. It needs Docker, Python 3 and the .NET 10 SDK. If Docker Hub rate-limits the PostgreSQL pull, pull `mirror.gcr.io/library/postgres:17.11` and tag it `postgres:17.11`.

**Last verified:** 2026-10-15. Environment: Ubuntu 24.04 container, 4 vCPU, 16 GB RAM, Docker 29.8.2, PostgreSQL 17.11, SQL Server 2022 CU27 (16.0.4295.3, collation `SQL_Latin1_General_CP1_CI_AS`), .NET SDK 10.0.112, EF Core 10.0.12, Npgsql EF Core provider 10.0.3. 27 SQL files and 18 EF Core checks passed.
